# Document Feature

## What this does

Writes a single delivery report so the outcome of a task2pr run survives outside the PR
description. All content comes from `loop_state` — nothing is recomputed. When the feature
ships a demo, it also captures screenshots of the running app and embeds them.

This skill is **feature-agnostic**: it reads whatever the loop produced and lays it out. It does
not know or care what the feature is.

---

## When to run

Always run after the gate passes (Step 5.5). Screenshots are conditional:

- `demo.enabled: true` in `config.json` **and** an offline/local mode is available → capture automatically.
- Otherwise → skip screenshots, note them as manual in the report.

---

## Steps

### 1 — Gather from `loop_state`

No new computation. Pull:

```
task                  gate_result / gate_cycles
feature               local_verify
plan (criteria)       config_keys_added
files_created         demo_wired
```

Acceptance criteria pass/fail comes from the gate evaluation — reuse it, do not re-test.
Test status is the PASS/FAIL already recorded by `write-tests` — do not re-run for counts.

### 2 — Capture screenshots (only when demo.enabled and an offline mode exists)

Add `playwright` as a dev dependency if absent, install the browser once, then shoot the routes:

```bash
npm install --save-dev playwright
npx playwright install chromium
```

Start the demo in its offline mode (no secrets needed), capture, stop:

```bash
mkdir -p docs/reports/<feature>
npm run dev &                 # ensure config protocol is the offline mode
DEMO_PID=$!
sleep 2
# one shot per meaningful screen the feature exposes:
npx playwright screenshot --wait-for-timeout=500 "http://localhost:${PORT}/" docs/reports/<feature>/01-landing.png
npx playwright screenshot --wait-for-timeout=500 "http://localhost:${PORT}/<success-route>" docs/reports/<feature>/02-success.png
kill $DEMO_PID 2>/dev/null
```

Rules for screenshots:
- Use the feature's **offline/local mode** only — never drive a live external service or IdP login.
- If only a live mode exists (e.g. credentials required), skip and mark the shot as "manual" in the report.
- Save under `docs/reports/<feature>/`. Never capture a screen that could render a secret.

### 3 — Write `docs/reports/<feature>.md`

Create `docs/reports/` if absent. Use this exact structure; omit a section only if the loop
produced nothing for it:

```markdown
# <Feature> — Delivery Report

_Generated by task2pr on <date> · branch `<branch>`_

## Task

<task description, verbatim>

## Acceptance criteria

| # | Criterion | Result |
|---|-----------|--------|
| 1 | <criterion> | ✅ / ❌ |

## Tests

<PASS / FAIL from write-tests — status only>

## Local verification

<verify-local result: PASS / SKIP / SKIP_MANUAL / FAIL, with the check lines>

## Screenshots

![Landing](./reports/<feature>/01-landing.png)
![Success](./reports/<feature>/02-success.png)

<or: "Manual — live mode requires credentials; capture after filling .env.">

## Files changed

- `<path>` — <one-line purpose>

## Config keys added

- `config.json` — <keys>
- `.env` — <keys> (user fills)

## Gate result

<PASS in N cycle(s)>
```

### 4 — Update `loop_state`

```yaml
report_path:  docs/reports/<feature>.md
screenshots:  [list of captured files]  # or []
```

### 5 — Report

```
document-feature complete.
  report:       docs/reports/<feature>.md
  screenshots:  <count captured, or "manual — see report">
```

---

## Rules

- **Read-only over source.** Only write `docs/reports/**` and (if needed) add the `playwright` devDependency.
- **No recomputation.** Criteria/test/gate status come straight from `loop_state`.
- **No secrets in the report or screenshots.** Never render `.env` values or a credential screen.
- **Screenshots use the offline mode only** — live external services are a manual step.
- Run after `run-acceptance-gate` PASS and before `create-pr`, so the PR can link the report.
