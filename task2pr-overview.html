Design principles

Five ideas hold it together

Everything below the orchestrator follows the same rules — which is what makes one loop work for any feature.

⚙︎

Config, not code

Endpoints, ports, secrets come from loadConfig() with ${VAR} expansion. Code branches on protocol, never a vendor name.

＋

Append-only config

generate-config only adds missing keys. Values you already filled in .env are never overwritten.

✓

The gate is the only door

A MUST checklist stands between work and a commit. Up to 3 fix cycles, then escalate — no broken code ships.

✦

Feature skills are generated

The base ships zero feature skills. grill-me interviews, then synthesises implement-<feature> on first use.

▶

Runnable by default

When a demo is wanted, a local server is wired and smoke-tested — so a human can try it in a browser.

Decision points

Four questions steer every run

?

Does an implement skill exist?

No → run grill-me, write the feature context, synthesise the skill. Yes → route straight to it.

?

Is this greenfield?

No package.json → bootstrap-project lays the toolchain. Otherwise skip untouched.

?

Is a demo enabled?

demo.enabled: true → wire a local server and smoke-test it. Otherwise library-only.

?

Did the gate pass?

PASS → create the PR. FAIL → targeted fix, re-evaluate; after 3 cycles, escalate.
